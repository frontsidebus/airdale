# Milestone v1.2: Consolidation & Quality

**Status:** ✅ SHIPPED 2026-04-18
**Phases:** 1-6
**Total Plans:** 14

## Overview

MERLIN v1.2 consolidated technical debt accumulated during rapid v1.0/v1.1 development. The work followed a strict dependency chain: clean up config and fix bugs (establishing a known-good baseline), wire in existing TTS and Whisper abstractions, refactor the web server for testability, add test coverage for the primary user-facing component, and stand up CI/CD to prevent future regressions. Each phase depended on the previous being stable — the ordering was driven by code dependencies, not arbitrary sequencing.

## Milestone Summary

**Key Decisions:**

- Housekeeping structured as point releases — independent, parallel fixes over a monolithic cleanup phase
- TTS integration driven by latency + quality, not just architecture — persistent connections reduce TTFB; consistent voice settings fix audible inconsistencies
- Web server refactor + tests split into separate phases — refactoring globals into DI first made the code testable; testing the old shape would mean rewriting tests after refactor
- CI/CD as final phase — tests and code quality had to exist before CI could enforce them
- Persistent `httpx.AsyncClient` per TTS backend eliminates per-call TCP overhead
- ElevenLabs WebSocket streaming uses `asyncio.Queue` for concurrent send/receive in `synthesize_ws_stream`
- TTS phrase cache stays in web server layer, checked before uncached text reaches `TTSClient`
- Whisper model default upgraded from `medium` to `large-v3-turbo` for better accuracy and speed
- `AppState` dataclass with 11 fields replaces all module-level mutable state in `web/server.py`
- Route handlers access shared state via `Depends(get_app_state)` callable, not global variables
- Monkeypatch module globals in tests (web/server.py still uses module-level state for early-boot logging)
- Pinned Docker images to full patch versions (ChromaDB 1.5.5, Whisper 0.8.3) for reproducible builds
- .NET CI builds only `SimConnectBridge.Tests.csproj` to avoid SimConnect SDK dependency on CI runners

**Issues Resolved:**

- 4 Phase 03 consumer-wiring bugs (incorrect `asyncio.to_thread` on async methods, `.close()` vs `.aclose()`) — fixed in close-out work, annotated in `03-VERIFICATION.md § Post-hoc Resolution`
- Python CI unblocked via `8587ba5 fix: unblock python CI + close out v1.2 (#71)`

**Issues Deferred:**

- None — all v1 requirements shipped

**Technical Debt Incurred:**

- VERIFICATION.md for Phase 03 was never formally re-run after consumer fixes; resolution was documented in-file rather than via a fresh verification pass
- `web/server.py` still uses module-level state for early-boot logging (noted during testing phase) — tests monkeypatch globals rather than use DI overrides. Acceptable for v1.2 but worth revisiting
