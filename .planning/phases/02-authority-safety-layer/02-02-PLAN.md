<objective>
Close the live defect on `main` where four systems already in the `set_aircraft_control`
enum — `trim`, `deice`, `fuel_selector`, `crossfeed` — resolve to SimConnect event names
the MSFS adapter has no handler for. Today MERLIN reports those actions as taken and
nothing happens.

distinct event names; `CommandMap` in `SimConnectManager.cs` registers 36. This plan adds
exactly the 20 that belong to enum-exposed systems, plus the parity guard that would have
caught the drift.

Output: 20 new `SimEventId` members and `CommandMap` entries, a C# table test, a Python
cross-language parity test, and a corrected `docs/AIRCRAFT_CONTROLS.md`.

This plan is confined to the C# adapter plus one Python test. Nothing in the authority
workstreams depends on it, and it depends on nothing.
