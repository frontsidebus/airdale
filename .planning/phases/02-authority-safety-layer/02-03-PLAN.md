<objective>
Bring semantic turn detection to the web path. VARC-01 delivered it for the local/CLI
path; the browser still endpoints on fixed RMS silence at 1200ms — three times the local
fixed fallback and eight times the semantic probe point.

Purpose: VARC-06. Architecture per D-20: the browser keeps the cheap acoustic gate and
decides *when* to ask; the server runs the existing `SmartTurnDetector` and decides
*whether* the turn is over. This is the recorded architectural principle (CLAUDE.md
decision 23) with the gate in JavaScript instead of Silero.

Output: a non-preprocessing webm decode helper, a `POST /api/turn-probe` endpoint,
`/api/status` fields that let the browser learn availability and thresholds in one call,
and a rate-limited browser probe loop with a 400ms fallback.

This is an independent workstream. It shares no logic with the authority plans and must
not be sequenced behind them.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `POST /api/turn-probe` | A new unauthenticated local HTTP surface accepting arbitrary binary uploads and spawning an ffmpeg subprocess per request |
| uploaded bytes → ffmpeg subprocess | Untrusted container data reaches a media decoder |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-03-01 | Denial of Service | `POST /api/turn-probe` unbounded probe rate | mitigate | Per-client throttle at half `turn_probe_silence_ms` server-side, plus a browser-side in-flight guard and re-probe interval. Severity high — `pollVAD` runs at ~60 Hz and each probe spawns ffmpeg, so an unthrottled endpoint is a local fork bomb |
| T-02-03-02 | Denial of Service | Unbounded upload size | mitigate | 2 MiB body cap rejected before any subprocess is spawned. Severity medium |
| T-02-03-03 | Tampering | Malformed webm reaching ffmpeg | mitigate | ffmpeg runs as a separate process with `pipe:0`/`pipe:1` only, no filesystem paths derived from input; non-zero exit returns `None` and is logged. Decode failure never raises to the client. Severity medium |
| T-02-03-04 | Information Disclosure | Utterance audio posted to a new endpoint | accept | The endpoint is served by the same local process that already receives the same audio over the chat WebSocket for transcription; no new data leaves the host and no audio is persisted to disk. Severity low |
| T-02-03-05 | Spoofing | Silence trimming corrupting the turn decision | mitigate | `decode_webm_to_samples` omits `preprocess_audio`, pinned by a structural test asserting the string is absent from the function source. Severity medium — a quietly wrong turn prediction is the failure mode `features.py`'s own docstring warns about |
| T-02-03-06 | Denial of Service | Hung probe blocking voice input | mitigate | Browser `AbortController` timeout plus the independent `vad_silence_ms` fallback stop, so voice input works even if every probe fails. Severity medium |
| T-02-03-SC | Tampering | pip / npm installs | accept | This plan installs no packages. `numpy`, `onnxruntime` and ffmpeg are already present; RESEARCH.md §Package Legitimacy Audit records zero new dependencies |
</threat_model>
