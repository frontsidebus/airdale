<objective>
Close the orchestrator half of Gap 1: stop reporting things that did not happen.

Purpose: the phase goal says authority must be "never ambiguous", and this phase's own
docstrings describe the false-confirmation class of bug as the worst failure mode the system
has. Three paths still produce one. Two of them live in `tools.py`, in the payload handed
directly to Claude, so they poison both the CLI and the browser: a critical command that the
authority floor refused still reports "Critical system change executed", and an undo that was
never transmitted still reports "Reversed GEAR_DOWN" *after* destroying the record that would
have let the pilot try again.

While in the same function, close WR-10 part 1: at `assisted` an *absent* safety verdict
currently takes the same branch as a *clean* one, so the one level whose job is to be
conservative fails open the moment telemetry is unreachable.

Output: one shared transmission predicate in `tools.py`, an undo path that pops only after a
confirmed transmission, a `safety_note` gated on that same predicate, an `assisted` branch
that withholds when there is no verdict, and tests that would have caught each defect.
</objective>

<interfaces>
Shapes this plan reasons about, taken from source rather than paraphrased.

`TelemetryClient.send_command` returns (sim_client.py):
  adapter ack, positive  -> {"success": True,  "message": "..."}
  adapter ack, negative   -> {"success": False, "message": "Unknown command"}     # NO "error" key
  ack timeout             -> {"success": False, "error": "Command timed out"}
  authority floor refusal -> {"success": False, "error": "Refused: MERLIN holds advisory
                              authority only (<reason>); nothing was sent to the aircraft.",
                              "refused": True, "authority_level": ..., "authority_reason": ...}
  send failure            -> {"success": False, "error": "Failed to send command: ..."}

The negative-ack shape is documented at sim_client.py as routine: "unregistered events return
exactly this ack shape routinely." It is the shape that carries no `error` key, and it is the
one every heuristic in this codebase has got wrong.

`set_aircraft_control` returns (tools.py):
  unknown control  -> {"error": ...}
  CMD-08 refusal   -> {"error": ..., "unresolvable": True, ...}
  safety blocked   -> {"error": ..., "blocked": True, "severity": "blocked"}
  advisory dry run -> {"advisory": True, "would_execute": ..., ...}   # no "error", no "success"
  assisted withhold-> {"withheld": True, ...}                          # no "error", no "success"
  otherwise        -> whatever send_command returned, plus "command" and "sim_value"

`CommandHistory` (command_history.py):
  get_undo_action() -> (system, action, value) | None
  last_command      -> CommandRecord | None      # peek, does not mutate
  pop_last()        -> CommandRecord | None      # mutates
  __len__()

`SafetyResult` (command_safety.py):
  SafetyResult(safe=True, command=...)                 -> severity == ""   # CLEAN verdict
  SafetyResult(safe=True, ..., severity="warning")     -> flagged
  SafetyResult(safe=False, ..., severity="blocked")    -> blocked

  CRITICAL: a clean verdict and an absent verdict BOTH render as `safety_severity == ""` in
  the current gate, because `safety_severity` is computed as
  `safety_result.severity if safety_result is not None else ""`. The review's suggested fix
  for WR-10 (`safety_severity in ("warning", "")`) would therefore withhold EVERY command at
  assisted, including clean ones. Discriminate on `safety_result is None`, never on the
  severity string.
