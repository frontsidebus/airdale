<objective>
Deliver the browser half of AUTH-06's "informs the pilot" clause, and close Gap 3.

Purpose: `OverrideDetector` builds two `ProactiveEvent` objects — "You've taken the flaps. I'm
advisory only until you're done." and "Back to full authority whenever you want me." — and puts
them on a queue that `web/server.py` constructs, subscribes and then never reads. Plan 02-13
gives the CLI a consumer and bounds the queue; this plan gives the browser one.

The badge added in plan 02-10 is not that consumer. It renders on a 10-second `pollStatus`
interval, so a watchdog latch or a pilot override can leave `FULL (configured)` on screen while
the gate is already refusing commands (IN-04), and it carries no words — it cannot say "you've
taken the flaps". AUTH-06 asks for an announcement, and an announcement is a message, not a
colour.

Output: one lifespan-owned pump draining the detector's queue and broadcasting an
`authority_event` frame to every registered `/ws/chat` socket, an `app.js` case that shows the
message and refreshes the badge from the frame's own authority fields, and a human checkpoint
covering the two items `02-VERIFICATION.md` flagged as unverifiable by static analysis.
</objective>

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| detector queue -> pump | A single process-wide consumer; if it dies, AUTH-06's browser half silently reverts to the state this plan is fixing |
| pump -> chat sockets | Server-initiated frames to every connected client, including clients that have gone away |
| server JSON -> DOM | `message` and `degraded_detail` embed telemetry-derived labels and arbitrary exception text |
| display -> pilot | An announcement the pilot misses has the same effect as one never sent |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-15-01 | Repudiation | An override drop the browser never reports | mitigate | A lifespan-owned pump with a per-event `try`/`except` and a done-callback that logs an unexpected death; tested for the frame shape and for the no-detector path. Severity high — this is the requirement AUTH-06 states |
| T-02-15-02 | Denial of Service | One failing socket ending the broadcast for every other client | mitigate | `_broadcast_chat` iterates a snapshot copy, discards a failing socket and continues; a dedicated test with one raising socket. Severity medium |
| T-02-15-03 | Denial of Service | A registry that grows for the life of the process as clients come and go | mitigate | `ws_chat` removes the socket in a `finally`, and `_broadcast_chat` discards any socket that fails a send.
