<objective>
Build the authority state machine that every other plan in this phase consumes, and
the pydantic-settings surface that seeds it.

Purpose: AUTH-01 requires a configurable authority level; AUTH-06 requires it to drop
on pilot override and restore afterwards; AUTH-07 requires it to latch when the
command path dies. All three are the same piece of mutable runtime state, and it must
live in a module that `sim_client.py` can import without creating a cycle (D-05 makes
`TelemetryClient` a consumer, and `sim_client.py` is the base of the dependency graph).

The same object also has to answer a fourth question that plans 02-09 and 02-10 depend
on: what does MERLIN report when the authority subsystem itself failed to start? The
only safe answer is "advisory, because I could not build the thing that decides" — a
distinct reason, never rendered as a deliberate configuration.

Output: `orchestrator/orchestrator/authority.py`, eight new `Settings` fields, their
`.env.example` and `docs/CONFIGURATION.md` documentation, and unit tests.
</objective>

  class AuthorityLevel(StrEnum): ADVISORY = "advisory", ASSISTED = "assisted", FULL = "full"
      # EXACTLY three members. D-17 rejected a fourth authority *state*; the degraded case
      # below is a fourth *reason*, which is what D-10 exists for.

  class AuthorityReason(StrEnum):
      CONFIG = "config", OVERRIDE = "override", WATCHDOG = "watchdog", DEGRADED = "degraded"

  SUPPORTED_AUTHORITY_LEVELS: tuple[str, ...] = ("advisory", "assisted", "full")
  def parse_authority_level(value: str) -> AuthorityLevel        # raises ValueError listing SUPPORTED_AUTHORITY_LEVELS

  class AuthorityState:
      def __init__(
          self,
          configured_level: AuthorityLevel,
          *,
          override_cooldown_s: float = 120.0,
          watchdog_max_timeouts: int = 3,
          clock: Callable[[], float] = time.monotonic,
          degraded_detail: str = "",     # non-empty => permanently degraded; see precedence
      ) -> None

      @classmethod
      def degraded_fallback(cls, detail: str) -> AuthorityState
          # ADVISORY / DEGRADED, built from enum literals only. Reads no Settings, takes no
          # other collaborator, so it is constructible from inside an `except` block that is
          # handling the failure of the normal construction path.

      @property level(self) -> AuthorityLevel        # effective level, lazily expires the cooldown
      @property reason(self) -> AuthorityReason      # why `level` holds its current value
      @property configured_level(self) -> AuthorityLevel
      @property watchdog_latched(self) -> bool
      @property consecutive_timeouts(self) -> int
      @property degraded(self) -> bool               # True iff degraded_detail is non-empty
      @property degraded_detail(self) -> str

      def record_override(self) -> bool              # True iff this call caused a level drop; always extends expiry
      def record_command_timeout(self) -> bool       # True iff this call latched the watchdog
      def record_command_success(self) -> None       # resets the counter; does NOT clear an existing latch
      def clear_watchdog(self) -> bool               # True iff a latch was cleared (D-18)
      def take_restore_event(self) -> bool           # True exactly once, on the first call after a cooldown lapses
      def summary(self) -> dict[str, Any]            # keys: level, reason, configured_level,
                                                     #       cooldown_remaining_s, watchdog_latched,
                                                     #       consecutive_timeouts, degraded_detail
</interfaces>

      0. If `degraded_detail` is non-empty, `level` is `ADVISORY` and `reason` is `DEGRADED`.

    `degraded_fallback(detail)` is a classmethod returning
    `cls(AuthorityLevel.ADVISORY, degraded_detail=detail)`. It must construct from enum
    literals only — no `Settings` read, no `parse_authority_level` call, no other
    collaborator — because plan 02-09 calls it from inside the `except` block that is
    handling the failure of the normal construction path, and a fallback that can fail the
    same way as the thing it is replacing is not a fallback. Log at ERROR on construction,
    naming `detail`, so a degraded start is never silent.

    `record_override()` sets the cooldown expiry to `clock() + override_cooldown_s`
    unconditionally (rolling timer, D-14: each new override pushes the expiry out) and
    returns True only when the effective level changed from non-advisory to advisory as a
    result. Log the transition at WARNING with old level -> new level, matching the logging
    style of `FlightPhaseDetector.update`.

    `record_command_timeout()` increments `_consecutive_timeouts`; when it reaches
    `watchdog_max_timeouts` it sets `_watchdog_latched = True` and returns True on the call
    that latched (subsequent timeouts return False). `record_command_success()` resets
    `_consecutive_timeouts` to 0 and must NOT clear an existing latch — per D-18 the only
    clear path is `clear_watchdog()`, because a latch that refuses commands can never
    produce the successful ack that would otherwise clear it.

    `clear_watchdog()` clears the latch and zeroes the counter, returning True only when a
    latch actually existed **and the state is not degraded**. On a degraded state it must
    return False and change nothing.

    `take_restore_event()` returns True exactly once, on the first call after an override
    cooldown has lapsed and no latch is active — it is how AUTH-06's "MERLIN announces the
    restore" is driven without a timer. Track a `_restore_pending` flag set when a cooldown
    is first observed to have expired. On a degraded state it must always return False;
    there is nothing to restore to.

    `summary()` returns a JSON-serialisable dict with exactly the keys named in the
    `<interfaces>` block. `cooldown_remaining_s` is `0.0` when no cooldown is active and is

    the badge, so it must always be present rather than conditionally emitted.
