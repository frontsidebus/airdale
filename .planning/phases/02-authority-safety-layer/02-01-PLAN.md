orchestrator/orchestrator/authority.py exports:

  class AuthorityLevel(StrEnum): ADVISORY = "advisory", ASSISTED = "assisted", FULL = "full"
  class AuthorityReason(StrEnum): CONFIG = "config", OVERRIDE = "override", WATCHDOG = "watchdog"
  SUPPORTED_AUTHORITY_LEVELS: tuple[str, ...] = ("advisory", "assisted", "full")
  def parse_authority_level(value: str) -> AuthorityLevel        # raises ValueError listing SUPPORTED_AUTHORITY_LEVELS

  class AuthorityState:
      def __init__(
          self,
          configured_level: AuthorityLevel,
          *,
          override_cooldown_s: float = 120.0,
          watchdog_max_timeouts: int = 3,
          clock: Callable[[], float] = time.monotonic,
      ) -> None

      @property level(self) -> AuthorityLevel        # effective level, lazily expires the cooldown
      @property reason(self) -> AuthorityReason      # why `level` holds its current value
      @property configured_level(self) -> AuthorityLevel
      @property watchdog_latched(self) -> bool
      @property consecutive_timeouts(self) -> int

      def record_override(self) -> bool              # True iff this call caused a level drop; always extends expiry
      def record_command_timeout(self) -> bool       # True iff this call latched the watchdog
      def record_command_success(self) -> None       # resets the counter; does NOT clear an existing latch
      def clear_watchdog(self) -> bool               # True iff a latch was cleared (D-18)
      def take_restore_event(self) -> bool           # True exactly once, on the first call after a cooldown lapses
      def summary(self) -> dict[str, Any]            # keys: level, reason, configured_level,
                                                     #       cooldown_remaining_s, watchdog_latched,
                                                     #       consecutive_timeouts
</interfaces>

    `AuthorityState` precedence, in this order, is the core of the class:
      1. If the watchdog is latched, `level` is `ADVISORY` and `reason` is `WATCHDOG` (D-17).
      2. Else if an override cooldown is active (clock() < expiry), `level` is `ADVISORY`
         and `reason` is `OVERRIDE` (D-06/AUTH-06).
      3. Else `level` is `configured_level` and `reason` is `CONFIG`.
    Reading `level` must lazily expire a lapsed cooldown — no background task.

    `record_override()` sets the cooldown expiry to `clock() + override_cooldown_s`
    unconditionally (rolling timer, D-14: each new override pushes the expiry out) and
    returns True only when the effective level changed from non-advisory to advisory as a
    result. Log the transition at WARNING with old level -> new level, matching the logging
    style of `FlightPhaseDetector.update`.

    `record_command_timeout()` increments `_consecutive_timeouts`; when it reaches
    `watchdog_max_timeouts` it sets `_watchdog_latched = True` and returns True on the call
    that latched (subsequent timeouts return False). `record_command_success()` resets
    `_consecutive_timeouts` to 0 and must NOT clear an existing latch — per D-18 the only
    clear path is `clear_watchdog()`, because a latch that refuses commands can never
    produce the successful ack that would otherwise clear it.

    `clear_watchdog()` clears the latch and zeroes the counter, returning True only when a
    latch actually existed. Log the clear at INFO.

    `take_restore_event()` returns True exactly once, on the first call after an override
    cooldown has lapsed and no latch is active — it is how AUTH-06's "MERLIN announces the
    restore" is driven without a timer. Track a `_restore_pending` flag set when a cooldown
    is first observed to have expired.

    `summary()` returns a JSON-serialisable dict with exactly the keys named in the
    `<interfaces>` block. `cooldown_remaining_s` is `0.0` when no cooldown is active and is
    rounded to one decimal, matching `HealthMonitor.summary()`'s `round(..., 1)` habit.

    Type hints on every signature (CLAUDE.md). Module docstring must state the
    no-package-imports constraint and why it exists, so a future contributor does not
    casually add `from .sim_client import SimState`.

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| operator config (`.env`) → `Settings` | Untrusted-by-typo input that decides whether MERLIN may command a simulated aircraft |
| `AuthorityState` → every command path | The single object whose `level` property is the phase's authorisation decision; every other plan trusts it |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-01-01 | Elevation of Privilege | `Settings.authority_level` parsing | mitigate | Unknown values raise a pydantic `ValidationError` at startup via `parse_authority_level`; there is no silent fallback branch. Severity high — a fail-open parse would grant `full` authority to a typo. Tested by an explicit `banana` case |
| T-02-01-02 | Elevation of Privilege | `AuthorityState` precedence order | mitigate | Watchdog latch is evaluated before cooldown, which is evaluated before configured level, so no non-advisory state can mask a latch. Severity high. Tested by the precedence test |
| T-02-01-03 | Denial of Service | Watchdog latch self-deadlock | mitigate | `record_command_success()` deliberately does not clear a latch; `clear_watchdog()` is the only clear path and is driven out of band by reconnect in plan 02-05 (D-18). Severity medium — a self-clearing-only latch would permanently disable command issuance |
| T-02-01-04 | Tampering | Import cycle forcing a duck-typed authority object | mitigate | `authority.py` imports nothing from the package, keeping the real type importable at the floor in `sim_client.py`; a structural test asserts it. Severity medium — a `TYPE_CHECKING`-only import would let any object satisfy the gate at runtime |
| T-02-01-05 | Repudiation | Advisory state with no attributable cause | mitigate | `AuthorityReason` is carried alongside the level and exposed through `summary()`, so "deferring to the pilot" and "cannot reach the sim" are never conflated (D-10). Severity low |
| T-02-01-SC | Tampering | pip installs | accept | This plan installs no packages. RESEARCH.md §Package Legitimacy Audit records zero new dependencies for the phase; slopcheck is not applicable |
