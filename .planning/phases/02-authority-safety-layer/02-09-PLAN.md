<objective>
Make the current authority level, and the reason for it, visible to the browser — and stop
the browser being told a dry run succeeded.

Purpose: AUTH-08 and the AUTH-02 half of RESEARCH B8. `_on_tool_result` in `web/server.py`
computes `success = not (isinstance(tool_result, dict) and "error" in tool_result)`, and the
advisory dry-run dict deliberately carries no `"error"` key — so today a command that was
never transmitted would render as `{"type": "command_status", "success": true,
"message": "GEAR DOWN"}`. That directly contradicts "the current mode is never ambiguous".

Separately, `/api/status` builds its response dict from scratch and never reads
`HealthMonitor`; `AppState` has no health field at all. Both entry points need the same
subsystems or the CLI and the browser will report different things.

Output: authority, health and override detection wired into the web `lifespan`; three new
`/api/status` fields plus a subsystem-health block; and distinct chat-WebSocket message types
for advisory and withheld results.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| browser → `GET /api/status` | An unauthenticated local HTTP surface that now reports authority state and subsystem health |
| server → chat WebSocket | The channel that tells the pilot what MERLIN did; a misclassified message here is a false report about the aircraft |

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-02-09-01 | Spoofing | Advisory dry run rendered as an executed command | mitigate | Explicit three-way classification in `_on_tool_result` on the `advisory` and `withheld` markers plan 02-04 froze, with a named regression test citing RESEARCH B8. Severity low. If the server is ever exposed beyond localhost this becomes a real finding and should be revisited with the rest of the endpoint surface |
| T-02-09-03 | Tampering | `/api/status` mutating authority state | mitigate | The route is `GET` and read-only; no endpoint added by this phase can set the authority level. Level changes come only from configuration at startup, override detection, and the watchdog. Severity high if violated, so the acceptance criteria assert no setter is introduced |
