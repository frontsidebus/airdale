<objective>
Make the current authority level, and the reason for it, visible to the browser — and stop
the browser being told a dry run succeeded.

Purpose: AUTH-08 and the AUTH-02 half of RESEARCH B8. `_on_tool_result` in `web/server.py`
computes `success = not (isinstance(tool_result, dict) and "error" in tool_result)`, and the
advisory dry-run dict deliberately carries no `"error"` key — so today a command that was
never transmitted would render as `{"type": "command_status", "success": true,
"message": "GEAR DOWN"}`. That directly contradicts "the current mode is never ambiguous".

Separately, `/api/status` builds its response dict from scratch and never reads
`HealthMonitor`; `AppState` has no health field at all. Both entry points need the same
subsystems or the CLI and the browser will report different things.

Third, and the reason Task 1 is written the way it is: the surrounding `lifespan` degrades
every optional component to `None` on failure and continues. That is right for STT, TTS and
the turn detector, where `None` means "this feature is off". It is exactly wrong for
`AuthorityState`, where `None` means "unrestricted" — the gate in `tools.py` reads `None` as
`FULL` and the floor in `sim_client.py` is guarded on `is not None`, so a swallowed exception
here would disable the gate, the floor, the watchdog and the override cooldown in one go, and
`/api/status` would report it as a deliberate `full` configuration. The authority objects are
therefore carved out of that pattern and fail toward *less* authority.

Output: authority, health and override detection wired into the web `lifespan` with a
fail-safe fallback; four new `/api/status` fields plus a subsystem-health block; and distinct
chat-WebSocket message types for advisory and withheld results.
</objective>

## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| `Settings` → web `lifespan` | The browser path's only composition root; a swallowed exception here decides whether every authority guard in the phase exists at runtime |
| browser → `GET /api/status` | An unauthenticated local HTTP surface that now reports authority state and subsystem health |
| server → chat WebSocket | The channel that tells the pilot what MERLIN did; a misclassified message here is a false report about the aircraft |
