<interfaces>
<!-- WebSocket endpoints and their message protocols from web/server.py -->

ws_chat (/ws/chat) message protocol:
  Client sends:
    {"text": "user message"}              -> triggers _stream_response
    {"type": "audio_start", "mime": "..."}  -> next binary = audio
    {"type": "interrupt"}                   -> cancel active response
  Server sends:
    {"type": "text", "content": "..."}      -> streamed text chunk
    {"type": "tts_audio", "size": N}        -> followed by binary MP3 frame
    {"type": "interrupted"}                 -> response was cancelled (barge-in)
    {"type": "done"}                        -> end of response
    {"type": "listening"}                   -> ready for input
    {"type": "error", "content": "..."}     -> error message

ws_telemetry (/ws/telemetry) message protocol:
  Server sends:
    {"type": "telemetry", "connected": bool, "data": {...} | null}
  Uses ws_lib.connect(telemetry_url) internally to proxy upstream

Key internal functions:
  _stream_response(ws, user_text, interrupt_event, state) -> streams Claude + TTS
  _cancel_active_response() -> sets interrupt_event, cancels task, sends "interrupted"
  _tts_websocket_stream(ws, tts_queue, interrupt, state) -> ElevenLabs WS TTS
  _tts_rest_fallback(ws, tts_queue, interrupt, state) -> REST TTS fallback

Barge-in flow: second send_json({"text": ...}) while first is streaming -> _cancel_active_response() called -> "interrupted" sent -> new _stream_response task created

TTS streaming: when elevenlabs_api_key is set, _stream_response creates _tts_websocket_stream task that opens ElevenLabs WS. For tests, either disable TTS (set elevenlabs_api_key="") or mock ws_lib.connect for ElevenLabs too.

Telemetry proxy: ws_telemetry calls ws_lib.connect(state.settings.telemetry_service_url) directly -- must patch web.server.ws_lib.connect.
</interfaces>

    The key challenge is mocking `ws_lib.connect` (which is `websockets.connect`). Use `unittest.mock.patch("web.server.ws_lib.connect")` as an async context manager.

    The mock must:
    1. Return an async context manager (use `AsyncMock` with `__aenter__` and `__aexit__`)
    2. The entered object must be an async iterable yielding JSON strings (telemetry data)
    3. The mock must eventually stop yielding (close the connection) so the test doesn't hang

    Pattern:
    ```python
    from unittest.mock import patch, AsyncMock, MagicMock
    import json

    async def test_telemetry_proxy_forwards_data(test_app, mock_app_state):
        telemetry_data = {"connected": True, "position": {"lat": 47.0, "lon": -122.0}}

        mock_ws = AsyncMock()
        # Make it async-iterable, yielding one message then stopping
        mock_ws.__aiter__ = MagicMock(return_value=iter([json.dumps(telemetry_data)]))
        # BUT __aiter__ must return an async iterator. Use an async generator instead:

        async def fake_upstream():
            yield json.dumps(telemetry_data)

        # Create async context manager mock
        mock_connect = AsyncMock()
        mock_connect.__aenter__.return_value = fake_upstream()  # This won't work directly

        # Better approach: create a proper async context manager class
    ```

    Recommended approach: Create a small helper class `FakeUpstreamWS` that is both an async context manager and an async iterable:
    ```python
    class FakeUpstreamWS:
        def __init__(self, messages):
            self._messages = messages
            self._index = 0

        async def __aenter__(self):
            return self

        async def __aexit__(self, *args):
            pass

        def __aiter__(self):
            return self

        async def __anext__(self):
            if self._index >= len(self._messages):
                raise StopAsyncIteration
            msg = self._messages[self._index]
            self._index += 1
            return msg
    ```

    Patch with: `@patch("web.server.ws_lib.connect", return_value=FakeUpstreamWS([json.dumps(data)]))`

    After the upstream closes (StopAsyncIteration / connection ends), the ws_telemetry handler loops back and tries to reconnect with a 3-second sleep. The test should disconnect the client WebSocket after receiving the expected messages, which triggers WebSocketDisconnect and exits cleanly.

    Use asyncio.wait_for with timeout on all receives.
