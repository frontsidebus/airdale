# v1.3 Reconciliation Audit

**Date:** 2026-07-29
**Scope:** Reconcile `.planning/ROADMAP.md` v1.3 against the actual state of `main`
**Trigger:** STATE.md Scope Divergence Note — "Before starting v1.3 Phase 2, reconcile"
**Method:** Read-only inspection of `main` (`16a2401`), all unmerged branches, and `docs/`. Every claim below cites a file, line, or command.

---

## Verdict

**Do not plan v1.3 Phase 2 as currently written.** Roughly half of it is already built, merged, documented, and wired into the live command path — while the half that is missing is the half that decides whether MERLIN is permitted to act at all.

Planning it as-written would re-specify seven working safety rules from scratch and under-specify the three capabilities that genuinely do not exist.

---

## 1. Phase 2 gap analysis — the headline

ROADMAP v1.3 Phase 2 reads:

> **Phase 2: Authority & Safety Layer** — Configurable authority levels (advisory/assisted/full), pilot override detection, watchdog timer, phase-aware command gating

Actual state:

| Deliverable | Status | Evidence |
|---|---|---|
| Phase-aware command gating | **BUILT & WIRED** | `command_safety.py` rules receive live `SimState` + `FlightPhase`; `_gear_up_on_ground`, `_flaps_full_at_cruise_speed`, `_throttle_idle_on_approach` all branch on phase |
| Envelope protection rules | **BUILT & WIRED** (never specified) | 7 rules at `command_safety.py:74-111`; `CommandSafetyCheck` instantiated at `tools.py:20`, threaded through `tools.py:223` and `tools.py:594` |
| Two-tier severity model | **BUILT & DOCUMENTED** (never specified) | `SafetyResult.severity` = `"blocked"` \| `"warning"`; `blocked` short-circuits, `warning` accumulates. Documented in `docs/SMART_CONTROLS.md:88-96` |
| Configurable authority levels (advisory/assisted/full) | **MISSING** | `grep -nE "authority\|watchdog\|override\|safety" orchestrator/orchestrator/config.py` → zero matches. No authority concept in code or docs. |
| Pilot override detection | **MISSING** | No match in `orchestrator/` or `docs/` |
| Watchdog timer | **MISSING** | No match in `orchestrator/` or `docs/` |

The severity model that exists (`blocked`/`warning`) is a **per-command envelope check**. It is not an authority model — it cannot express "MERLIN may advise but not actuate," which is what advisory/assisted/full means. The two are complementary, not substitutes: authority decides *whether MERLIN may act at all*, severity decides *whether this specific command is safe right now*.

### Proposed Phase 2 rescope

Cut the two already-delivered items. Retain and sharpen the three real ones:

1. **Authority levels in config** — `authority_level: advisory | assisted | full`, enforced at the single choke point where `set_aircraft_control` reaches SimConnect. `advisory` = MERLIN describes the action and does not send it; `assisted` = sends only non-`warning` commands; `full` = current behavior.
2. **Pilot override detection** — detect manual control input contradicting a MERLIN-issued command; surface it and drop authority to `advisory` for a cooldown. Requires deciding which telemetry fields witness manual input.
3. **Watchdog timer** — bound the time between command dispatch and `AdapterCommandAck`; on expiry, stop issuing commands and inform the pilot. `command_verifier.py` already polls for post-command state confirmation and is the natural host.

Add an explicit non-goal: *this phase does not add new command types or new envelope rules.*

## 4. Root cause: v1.3 has no REQUIREMENTS.md

v1.2 had requirement IDs (HSKP-01…07, TTS-01…07, WHSP-01…04, WSRV-01…04, WTST-01…07, CICD-01…07) that every plan declared and every verifier traced. v1.3 has none. ### Salvage from `test/phase3-coverage`

**This branch must not be merged.** It forked at `e5c569a`, **23 commits behind** `main`; `git diff main..test/phase3-coverage` shows 10,076 deletions — merging would revert `callouts.py`, `command_safety.py`, `proactive_monitor.py`, `deviation_monitor.py`, all v1.2 LEARNINGS files, and `docs/SMART_CONTROLS.md`.

Its single commit (`8c94b7d`) is purely additive — 1,534 insertions, 0 deletions — and was tested file-by-file against current `main`:

| File | Verdict | Evidence |
|---|---|---|
| `test_command_safety.py` | **TAKE AS-IS** | Absent on `main`. 296 lines, 24 tests. **Passes 24/24 unmodified** against current `command_safety.py`. |
| `test_procedures.py` | **REPLACE** | Branch is a strict superset — all 16 of `main`'s tests present, plus 9 more (25 total). Zero lost. Passes. |
| `test_command_verifier.py` | **DEFER** | 39 tests vs `main`'s 28, but **zero test-name overlap** — two disjoint suites for one module. Both pass. Merging needs manual dedup; not mechanical. |

**Recommended immediate action:** cherry-pick `test_command_safety.py` and `test_procedures.py`. That closes the project's only safety-critical coverage gap with ~600 lines of already-written, already-passing tests.

Two items need a decision rather than a cleanup:

- **`docs/phase2-controls` + `feat/fuel-controls`** add command *types* (engine management, fuel selection). If those are wanted, they expand the surface the Phase 2 authority layer must gate — so decide before Phase 2 is planned, not after. - **`rio/*` + `feature/local-inference-architecture`** describe a different architectural direction (LLM abstraction, local inference) against a separate `rio` remote, 210 commits behind. Combined with `docs/MIGRATION_V1_V2.md` and `chore/v2-ci-updates`, this looks like a dormant v2 direction that deserves an explicit accept-or-abandon decision.

## Recommended sequence

1. **Write `.planning/REQUIREMENTS.md` for v1.3**, with retroactive IDs for what is already built (§4). Without this, the drift recurs.
2. **Update `CLAUDE.md`** — 13 modules, 10 docs, the STT/TTS backend table (§5). Cheap, and it is the file every future plan reads for context.
3. **Fix ROADMAP v1.3** — rescope Phase 2 to the three real deliverables, drop the stale Phase 1 branch reference, note the `procedures.py` overlap on Phase 3 (§1–3).
4. **Cherry-pick the two clean test salvages** (§6). Closes the `command_safety.py` gap for near-zero effort.
5. **Decide on `docs/phase2-controls` / `feat/fuel-controls`** before planning Phase 2 (§7).
6. **Then plan Phase 2**, and run `/gsd:verify-phase` on it — three of six v1.2 phases skipped verification, and the one phase that ran it found six real defects behind a green suite.
7. Triage the 11 `worktree-agent-*` branches and 5 stashes; decide accept-or-abandon on the RIO/v2 direction.
